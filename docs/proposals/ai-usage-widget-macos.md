# 企画書: AI Usage Dashboard Widget for macOS(仮称: "Quota")

- ステータス: 草案 v0.1
- 作成日: 2026-07-02
- 種別: macOS デスクトップウィジェット / メニューバーアプリ

---

## 1. 背景・課題

ChatGPT、Claude、Gemini など複数の AI サービスを併用するユーザーが増えている。
これらのサービスには次のような利用制限があるが、**確認手段がサービスごとにバラバラで、
しかも分かりにくい**。

- 5時間ごとのローリングウィンドウ制限(いつリセットされるのか直感的に分からない)
- 週間・月間の上限(プランによって異なる)
- モデルごとの別枠制限(高性能モデルだけ先に枯渇する等)

その結果、次のような不満が発生している。

- 「今使い切ると何時に復活するのか」を毎回サービス側の画面で確認する必要がある
- 大きな作業を始める前に「残量が足りるか」を判断できない
- 複数サービスを併用して残量を使い分けたいのに、横断で見る場所がない

## 2. プロダクト概要

**複数の AI サービスの利用制限(リセット時刻・残量)を、macOS のデスクトップ
ウィジェット/メニューバーで一括確認できるアプリ。**

一目で分かるのは次の3点:

1. **今すぐ使えるか** — 各サービスの5時間枠の残量ゲージ
2. **いつ復活するか** — リセット時刻のカウントダウン("あと1h23m")
3. **今週/今月あとどれくらいか** — 週間・月間クォータの消化率

## 3. ターゲットユーザー

- 複数の AI サブスク(ChatGPT Plus / Claude Pro・Max / Gemini 等)を併用するパワーユーザー
- AI コーディングツール(Claude Code, Cursor, Copilot 等)を業務で使う開発者
- 制限に達すると業務が止まるため、残量を見ながら作業配分したい人

## 4. 主要機能

### 4.1 MVP(v1)

| 機能 | 内容 |
|------|------|
| サービス登録 | 対応サービスのアカウントを追加(まず Claude / ChatGPT / Gemini) |
| 5時間枠ゲージ | 残り使用量をプログレスバー表示 + リセットまでのカウントダウン |
| 週間/月間ビュー | 週・月クォータの消化率と履歴のミニグラフ |
| メニューバー常駐 | 最も逼迫しているサービスの残量をメニューバーに常時表示 |
| デスクトップウィジェット | WidgetKit で S/M/L サイズのウィジェット提供 |
| 通知 | 「残量20%を切った」「枠がリセットされた」を通知センターに送る |

### 4.2 将来機能(v2以降)

- 使用ペースの予測(「このペースだと今日の18時に枯渇」)
- サービス横断のおすすめ(「Claude が枯渇中。GPT は残70%」)
- チーム/複数アカウント切り替え
- iOS ウィジェット版(iCloud 同期)
- CLI / Raycast 拡張

## 5. データ取得方式(最重要の技術課題)

各サービスが公式に残量 API を公開しているとは限らないため、取得方式は
サービスごとにプラガブルにする。

| 方式 | 説明 | 例 |
|------|------|-----|
| 公式 API | 公式のusage/quota APIがある場合はそれを使う | Claude Code の usage 情報、各社 API の rate limit ヘッダ |
| ローカルログ解析 | CLIツールのローカルログ/設定から使用量を推定 | `~/.claude` 配下のセッションログ等 |
| セッション連携 | ユーザーのブラウザセッションの認証情報で内部APIを参照 | 各サービスのアカウント usage エンドポイント |
| 手動/半自動記録 | 上記が使えない場合、ユーザー操作でカウント | 最終フォールバック |

**リスク**: 内部 API 依存の方式は仕様変更・規約面の懸念がある。
→ v1 は「公式に取れるもの + ローカルログ解析」を中心にし、規約グレーな方式は
オプトインの拡張として分離する。プラグイン構造にして壊れたソースだけ差し替え可能にする。

## 6. 技術スタック(案)

- 言語/UI: Swift + SwiftUI(WidgetKit, MenuBarExtra)
- 常駐: メニューバーアプリ本体 + App Group でウィジェットとデータ共有
- データ更新: バックグラウンドで数分おきにポーリング(ウィジェットは timeline reload)
- 保存: ローカル(SQLite or SwiftData)。認証情報は Keychain。外部サーバーには送らない
- 配布: まず Developer ID + notarization で直販(内部API連携があるとMac App Store審査は難しい可能性)

## 7. マネタイズ(案)

- フリーミアム: 無料 = 1サービスまで / 有料 = 無制限 + 通知 + 予測機能
- 買い切り 1,500〜3,000円 or 年額サブスク(Gumroad / Lemon Squeezy / Paddle で直販)
- 「開発者向けツール」として Product Hunt / X / Hacker News で告知

## 8. 競合・類似

- 各サービス公式の usage 画面(横断できない・リセット時刻が分かりにくい)
- Claude Code の `/status`、ccusage 等の CLI ツール(単一サービス・開発者限定)
- **横断・GUI・ウィジェットという組み合わせが空いている**のが本企画のポジション

## 9. リスクと対策

| リスク | 対策 |
|--------|------|
| サービス側の仕様変更で取得が壊れる | ソースをプラグイン化し個別アップデート。壊れたら「取得不可」表示に劣化 |
| 利用規約への抵触 | 公式手段優先。グレーな方式はユーザーのオプトイン + 免責明示 |
| 制限仕様自体の変更(5時間枠の廃止等) | 表示モデルを「ローリング枠」「固定期間枠」の抽象で持ち、設定で追随 |

## 10. マイルストーン(案)

1. **PoC(1週間)**: Claude 1サービスの残量取得 + メニューバー表示のみ
2. **MVP(+2〜3週間)**: 3サービス対応、ウィジェット、通知
3. **公開(+1〜2週間)**: 直販サイト、課金、Product Hunt ローンチ

## 11. 成功指標

- PoC: 自分が毎日見るツールになるか(ドッグフーディング)
- 公開後3ヶ月: 有料転換 100件 or MAU 1,000
